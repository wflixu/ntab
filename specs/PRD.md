# ntab 智能书签管理系统 - 产品需求文档 (PRD)

## 版本信息

- **版本**: 1.0.0
- **日期**: 2026-04-15
- **状态**: 设计阶段
- **项目**: ntab Chrome扩展

---

## 1. 项目概述

### 1.1 目标

为ntab Chrome扩展添加完整的智能书签管理系统，利用浏览器历史记录和大模型API提供智能化的书签管理体验。

### 1.2 技术栈

- **前端框架**: Vue 3 + TypeScript
- **UI组件**: PrimeVue 4
- **状态管理**: Pinia
- **存储**: IndexedDB + chrome.storage.local
- **API调用**: fetch API
- **拖拽**: vuedraggable

### 1.3 项目范围

本项目分为两个主要部分：
1. **设置页面** - 书签整理功能和AI配置
2. **主页组件** - WebNavi书签导航的重新设计

## 3. 设计决策

### 3.1 用户确认的决策

| 决策项 | 选择 | 理由 |
|--------|------|------|
| API Key存储 | chrome.storage.local + 加密 | 安全性高，适合程序员工具 |
| 计费控制 | 月度Token上限 | 防止意外超支，默认100k tokens |
| 数据处理 | 本地处理 | 隐私保护，不上传到服务器 |
| 布局风格 | 列表+网格切换 | 用户可选择显示方式 |
| AI集成方式 | 快捷按钮+悬浮面板+独立页面 | 多种方式满足不同场景 |
| 存储方案 | IndexedDB | 支持大量书签，避免localStorage限制 |

### 3.2 设计原则

1. **渐进增强** - 保持现有简洁风格，逐步添加功能
2. **模块化** - 功能解耦，便于维护
3. **一致性** - 与现有UI风格保持一致
4. **可配置** - 用户可自定义显示和行为
5. **向后兼容** - 不影响现有用户数据

## 4. 用户故事

### 4.1 首次使用用户

**故事**: 作为一名新用户，我希望能够快速建立一个有个人特色的主页

**接受标准**:
- 首次打开时自动检测空状态
- 展示引导流程
- 从历史记录中智能推荐常用网站
- 一键添加推荐网站到主页

### 4.2 AI功能用户

**故事**: 作为一名高级用户，我希望使用AI来管理我的书签

**接受标准**:
- 可以配置多个AI提供商
- 可以查看Token使用情况
- AI功能失败时自动降级到本地算法
- API Key安全存储

### 4.3 书签整理用户

**故事**: 作为一名书签较多的用户，我希望能够清理无效和重复的书签

**接受标准**:
- 可以检测重复书签
- 可以查看长期未访问的书签
- 可以检测死链
- 可以批量操作

## 5. 用户体验流程

### 5.1 首次使用引导

```
首次打开检测
     │
     ▼
检测 my-sites 是否为空
     │
     ├─→ 不为空 → 正常显示 WebNavi
     │
     └─→ 为空 → 检测是否已完成引导
                │
                ├─→ 已完成 → 显示空状态
                │
                └─→ 未完成 → 显示引导流程
                            - 步骤1: 欢迎
                            - 步骤2: 快速选择（历史记录推荐）
                            - 步骤3: 完成
                            - 步骤4: AI功能发现
```

### 5.2 AI配置流程

1. 用户进入设置页面
2. 选择AI提供商（DeepSeek/OpenAI/自定义）
3. 输入API Endpoint和Key
4. 点击"验证连接"测试配置
5. 保存配置

### 5.3 书签整理流程

1. 用户进入设置页面
2. 选择整理功能（推荐/清理/死链检测）
3. 系统分析数据
4. 展示结果
5. 用户选择操作
6. 执行批量操作

## 7. 非功能性需求

### 7.1 性能

- 支持1000+书签不卡顿
- AI操作响应时间<3秒
- 页面加载时间<1秒

### 7.2 安全

- API Key加密存储
- 数据本地处理
- 不上传敏感信息

### 7.3 兼容性

- 支持Chrome 88+
- 支持Firefox 100+
- 向后兼容现有数据

## 9. 风险与限制

### 9.1 风险

- AI API可用性依赖第三方
- 用户可能不愿意配置API Key
- 大量书签可能影响性能

### 9.2 限制

- AI功能需要网络连接
- Token消耗需要用户承担
- CORS限制可能影响某些功能
